## 6. Карта прогресса (самооценка по требованию)

Не онбординг-тест (сознательно отклонён — риск оттолкнуть новичка) — а
**необязательный, всегда доступный** инструмент, который пользователь
открывает сам, когда хочет понять "где я нахожусь". Ключевое отличие от
онбординга — не барьер на входе, а инструмент по запросу.

- Форма — **radar/паутинная диаграмма** по крупным осям курикулума
  (склонение, спряжение, сандхи, лексика, синтаксис), каждая ось —
  агрегированный `successRate` по всей области.
- "Стрелки" — не связи между узлами (это уже пробовали как отдельную
  диаграмму навыков и отклонили для полноты охвата, см. §8 ниже) — а
  интерактивность: клик по слабой оси → прямой переход в соответствующий
  раздел курикулума (§2, `01-curriculum-vs-catalog.md`). По сути
  расширенная, визуализированная версия блока "слабые места" с
  дашборда, но на весь экран, с возможностью провалиться в детали по
  каждой оси.
- Открытый вопрос: агрегация `successRate` по крупным осям (не по
  отдельным парам падежей, как на дашборде) — нужна отдельная формула
  свёртки, не рассмотрена в деталях (решена ниже).

**Формула агрегации (решено).** Наивное среднее по всем ответам ломается на
перекосах выборки — например, 500 ответов на a-основы с 95% точностью и
2 ответа на спряжение со 100% точностью дадут ложное впечатление, что обе
области одинаково сильны. Агрегация в три уровня, снизу вверх:

1. **Единица** (одна пара падеж+число или одна словоформа глагола):
   ```
   item_confidence = wilson_lower_bound(correct, attempts) × decay(days_since_last)
   ```
   — если `attempts == 0`, `item_confidence = 0` явно, не пропускается.
   Нижняя граница Уилсона вместо голого `correct/attempts` защищает от
   ложной уверенности при малой выборке (1 из 1 не должно давать 100%).
   `decay(days)` — экспоненциальное затухание со временем с последнего
   ответа (см. streak/decay-модель, обсуждалась ранее как дополнение к SRS).
2. **Урок** (конкретный тип основы/глагольный класс):
   ```
   lesson_score = Σ(item_confidence × frequency_weight) / Σ(frequency_weight)
   ```
   — взвешивание по частотности формы (Nom./Acc./Instr. весят больше
   редкого Voc.), не равномерное усреднение по всем 24 клеткам парадигмы.
3. **Область** (ось радара — "Спряжение" целиком):
   ```
   area_score = mean(lesson_score по всем урокам области, включая
                      ещё не начатые = 0)
   ```
   — усреднение по **урокам**, не по сырым формам напрямую: иначе урок с
   большим числом форм (например, согласные основы со всеми подтипами)
   задавит своим объёмом урок с малым числом форм, хотя это вопрос объёма
   материала, а не мастерства. Непройденные уроки включаются как 0, чтобы
   не начатая область на радаре выглядела как честный провал, а не как
   "нет данных".

Формула ещё не реализована в statistics-service — это блокер для
полноценного блока "слабые места" на дашборде, см.
`docs/agents/tasks/task-02-dashboard.md`.

## 8. Почему не единая диаграмма/карта навыков вместо дерева

Ранняя версия обсуждения предлагала единую диаграмму — сначала 2, затем 5
параллельных "треков", сходящихся в "Синтаксис"/"Чтение" и раскрывающихся
в целевые тексты. Отклонена по двум причинам:

- **Диаграмма — инструмент для показа связей, не для полного
  перечисления.** Попытка впихнуть всю грамматику в один флоучарт даёт
  нечитаемую простыню стрелок — для "показать всё" нужен список/дерево
  (§2), для "показать логику переходов" — отдельная, более грубая
  иллюстрация вне основного UI.
- **Сандхи и лексика не гейтят синтаксис, а идут к чтению параллельно** —
  в курикулуме (§2) они физически отдельные top-level разделы (2.8,
  каталог §3.1), не вложенные в "Существительные"/"Глагол"; их прогресс
  учитывается в метрике готовности к тексту (§3.2) наравне с морфологией.
- Карта прогресса из §6 не противоречит этому выводу — это не карта
  зависимостей между темами, а панель диагностики текущего состояния
  пользователя, принципиально другая задача.
