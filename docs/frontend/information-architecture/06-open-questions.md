# §9. Открытые вопросы, требующие решения перед реализацией

> Часть [information-architecture.md](../information-architecture.md).
> Эскалируются Агенту 0 (Оркестратор) при постановке связанных задач.

---

- §2.12 (письмо/произношение): делать ли опциональным для пользователей,
  уже знающих деванагари.
- §3.2 (библиотека, текст готовности): точная формула "непрерывной
  метрики готовности" текста — взвешивать ли редкие слова иначе, чем
  частотные.
- §3.1 (браузер словаря): нужен ли он как самостоятельная фича, или
  достаточно точки входа через уроки — решить перед проектированием API
  под виртуализированный список.
- §3.1 (личные списки): что происходит с "сырыми" элементами списка
  (слово без связи с `declension_stems`) при генерации квиза — нужна ли
  для них отдельная, упрощённая механика (например, простое
  запоминание/флеш-карта без падежных форм), раз для них не сгенерировать
  полную парадигму без грамматического разбора.
- §3.2 (библиотека): полнотекстовый поиск по формам зависит от готовности
  блока V (Vidyut-service, `vidyut-cheda`) — до его готовности возможен
  только поиск по словарным леммам, не по произвольным словоформам.
- §7 (источники текстов): нужно ли явное поле `license`/`source_type`
  (public domain vs под правом) в модели произведения — чтобы платформа
  сама не давала возможность добавить контент с неясным статусом прав.
