## 3.1 Лексика → браузер словаря + личные списки

- **Обучение (курикулумная часть)** — уроки лексики (`quizzes/vocabulary`
  ✅), 20–40 слов на урок, обычная таблица без пагинации уместна.
- **Браузер всего словаря (2000+ слов)** — поиск (IAST/деванагари/перевод)
  как основной вход, фильтры-чипсы (статус, тип основы) вместо сортировки
  по колонкам, виртуализированный список с подгрузкой при прокрутке вместо
  постраничной `DataTable`.
- **Личные списки слов (новое).** Отдельная, пользовательская структура
  поверх курикулума и каталога — не подмена уроков, а произвольная
  подборка. Кнопка «добавить в список» доступна на любом слове где угодно
  в интерфейсе (словарь, результат поиска по строфам, разбор стиха
  sangraha, чтение текста) — modal с выбором существующего списка или
  созданием нового.
  - Модель данных:
    `content.user_word_lists (id, userId, title, createdAt)`,
    `content.user_word_list_items (listId, stemId|conjugationId, addedAt)`.
    Ещё не реализована — см. открытый вопрос в `content-service.md`.
  - Элемент списка ссылается на существующую `declension_stems`/
    `conjugation_stems`-запись; если слово встретилось в
    непроиндексированном тексте и такой записи ещё нет — сохраняется как
    "сырая" пара IAST+перевод с возможностью связать с реальной основой
    позже.
  - «Изучать список» = обычная квиз-сессия
    (`DeclensionQuizGeneratorService`), источник основ — список
    пользователя, а не урок/`VowelType`. Технически — новый режим выбора
    основ на входе того же генератора, не новый сервис.
- Словообразовательные гнёзда ⛔ — отдельная лексикографическая фича, не
  часть браузера.

## 3.2 Тексты → библиотека

- Карточки произведений (не пункты дерева) — метаданные объёма
  (проза/поэма/эпос, число глав/строф), непрерывная метрика готовности
  (не бинарный статус, а % понятной лексики, вычислимый через
  Vidyut-морфологию).
- Фильтры по объёму и жанру (короткие/поэмы/эпос/готово к чтению).
- **Идентификация строфы** — стабильный адрес `произведение.глава.строфа`
  (`bhagavadgita.2.47`) — нужен и для глубоких ссылок, и как `source_ref`
  в `usage_examples`. Соотнести с существующей моделью Work→Chapter→Verse
  в `sangraha-service.md`.
- **Поиск по корпусу** возвращает и произведения, и отдельные строфы, где
  встречается искомое слово/форма — две секции результата, не единый
  список; каждая строфа-результат показывает морфологический разбор
  найденного слова — требует, чтобы поиск шёл по уже сегментированному
  через `vidyut-cheda` тексту, не по сырой строке.
- Клик по найденной строфе — глубокая ссылка на точный адрес
  (`/texts/bhagavadgita/2/47`), локальная навигация произведения
  прокручивается/подсвечивает нужное место.
- Interlinear-режим — свойство страницы конкретного произведения, не
  отдельный каталожный узел.
- **Источники текстов** — не любой учебник можно использовать одинаково
  свободно, см. `05-text-sources.md`.
