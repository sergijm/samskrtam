# US-LEX-02 — Активное вспоминание слова по переводу (обратное направление)

> Домен: Lexicon · Тип: `VOCABULARY_WORD`, направление «перевод → слово» (план; прямое направление «слово → перевод» уже реализовано)
> Связанные файлы: [quest-catalog.md §5](../../../services/quest-catalog.md#5-лексика) · [quest-types-overview.md, тип №18](../../../services/quest-types-overview.md#лексика)

## История

Как ученик, уже узнающий слова санскрита на слух, я хочу тренироваться вспоминать
санскритское слово по его русскому/английскому переводу (а не наоборот), чтобы
развивать активный словарный запас — способность вспомнить слово самому, а не только
узнать его при чтении.

## Сценарий

1. Ученик открывает урок «Слова: природа» с включённым режимом «перевод → слово».
2. Система показывает перевод («гора») и просит ввести санскритское слово.
3. Ученик вводит ответ (`parvataḥ`).
4. Система проверяет ответ с учётом синонимичных допустимых вариантов, если для слова заранее заданы альтернативные приемлемые формы записи (например, допускать вариант без диакритики).
5. Прогресс обновляется отдельно от прогресса «слово → перевод» для того же слова (см. критерии).

## Критерии приёмки

- [ ] Единица прогресса для направления «перевод → слово» — отдельный `itemId`, отличный от «слово → перевод» того же `VocabularyWord` (это разные навыки: узнавание vs активное вспоминание, см. `quest-item-model.md §1`).
- [ ] Обратное направление доступно только для слов, у которых уже есть прогресс `MASTERED` или `DUE` в прямом направлении — ученик сначала узнаёт слово пассивно, потом тренирует активное вспоминание (мягкая зависимость на уровне отбора Quest, не блокирующая архитектурно).
- [ ] Проверка ответа допускает варианты транслитерации (регистр, наличие/отсутствие части диакритики) — сверка не строго посимвольная.
- [ ] Дистракторов нет — режим всегда FREE_TEXT (выбор из вариантов не тренирует активное вспоминание).

## Вне рамок

- Автоматический подбор «мягкой зависимости» между направлениями на основе прогресса — конкретный алгоритм отбора не описан в этой истории, это задача `SessionItemSelector` при реализации.
