# US-MORPH-02 — Комплексные задания по склонению

> Домен: Morphology · Типы: `CASE_RECOGNITION`, `DECLENSION_MATCH` · API v2, curriculum-service
> Связанные файлы: [curriculum-quest-items.md §2.3–2.4](../../../services/curriculum-quest-items.md#23-case_recognition--тип-3-комплексный-определить-падеж) ·
> [US-MORPH-01 — простые задания](./user-story-case-drill.md)

## История

Как ученик, уже прошедший простые задания на конкретную основу (US-MORPH-01), я хочу
проверить обратный навык — узнавание падежа по готовой форме — и умение видеть всю
парадигму сразу, а не по одной форме за раз, чтобы убедиться, что я не просто запомнил
порядок вопросов, а действительно различаю окончания.

## Сценарий A — CASE_RECOGNITION («определить падеж»)

1. Ученику показывается готовая словоформа (`devān`) без леммы в явном виде.
2. Ученик выбирает один составной вариант из списка (`Accusative Plural`), а не падеж и
   число по отдельности.
3. Если форма грамматически неоднозначна без рода в рамках темы (омонимия с формой другого
   рода того же класса основ) — вариант включает и род (`Instrumental Plural Neuter`);
   в остальных случаях род не показывается и не спрашивается.
4. Дистракторы — другие грамматически валидные комбинации падеж+число[+род], типичные для
   этой же основы (не случайный шум, а реальная путаница, например Accusative Plural ↔
   Nominative Plural у некоторых основ).
5. Прогресс и SM-2 — как в US-MORPH-01, единица прогресса — конкретный `QuestItem.id`.

## Сценарий B — DECLENSION_MATCH («соединить пары»)

1. Ученику показывается фиксированный набор пар (размер задаётся конфигом
   curriculum-service, см. `curriculum-quest-items.md` §4, не виден ученику как настройка) —
   слева словоформы одной леммы, справа перемешанные подписи падеж+число.
2. Ученик соединяет пары кликами/drag-and-drop (UI-деталь — задача Агента 3, здесь не
   специфицируется).
3. Ответ отправляется целиком (все сопоставления сразу), засчитывается только полное
   совпадение всех пар — без частичного зачёта в первой версии.
4. При ошибке показываются все верные сопоставления; прогресс SM-2 обновляется для
   `QuestItem` целиком (не по отдельным парам — единица прогресса это всё задание).

## Критерии приёмки

- [ ] CASE_RECOGNITION: правильный вариант всегда единственный среди предложенных (нет двух формально верных ответов).
- [ ] CASE_RECOGNITION: род включается в вариант ответа только когда `genderRequired = true` в payload — иначе не показывается.
- [ ] DECLENSION_MATCH: ответ либо полностью верный, либо полностью неверный — частичного зачёта нет.
- [ ] Оба типа используют одну и ту же лемму/парадигму, что и простые задания той же темы (нет расхождений в словоформах между типами).

## Вне рамок

- Частичный зачёт в DECLENSION_MATCH (например, 4 из 5 пар верно) — не в этой версии.
- Настройка числа пар учеником — фиксируется конфигом, не UI-параметром.
