# Массовый просмотр и анализ стихов по произвольному списку id

> Дополняет `sangraha-service.md` §4 (API) и §7 (Frontend). Повод: часть корпуса
> загружается внешним скриптом в обход UI (см. `verse-word-grammar.md` §1а/§1б) —
> нужна возможность посмотреть и
> прогнать LLM-анализ по произвольному набору `verseId`, не привязанному к
> одной главе (в отличие от уже существующей `POST /chapters/{chapterId}/
> verses/analyze-all`).

## `POST /api/v1/sangraha/verse` (тело — `{ verseIds: UUID[] }`)

Права — как остальной read в §4 (любой аутентифицированный пользователь).
Тело — `VersesBatchRequestDto` (`verseIds` — список `verseId` произвольного
размера, **без ограничения сверху** на этом эндпоинте — это просто чтение,
в отличие от анализа, где размер имеет значение, см. ниже). `id`, для
которого стиха нет или он мягко удалён (`deletedAt != null`) — просто
отсутствует в ответе, без ошибки (тот же принцип, что у
`/sangraha/internal/content/verses/batch`, §9).

Ответ `VersesBatchResponseDto`: `verses` — массив, каждый элемент: `id`,
`workSlug`, `workTitleRu`, `workTitleEn`, `chapterSlug`, `chapterTitleRu`,
`chapterTitleEn`, `verseOrderIndex`, `textIastPreview` (та же обрезка текста,
что в дереве `GET /works/{workSlug}`, §4; источник — `textIast`, а если он
пуст/отсутствует (например DRAFT-стих) — fallback на `rawText`), **`status`**
(DRAFT|ANALYZING|
ANALYZED|FAILED — в отличие от внутреннего `/verses/batch`, эта ручка не
фильтрует по статусу и обязана его отдавать, иначе непонятно, что показывать
на новой странице, см. ниже). Порядок элементов — по порядку `id` в запросе.

## `POST /api/v1/sangraha/verse/analysis`

Права — `ADMIN` (как весь write-контур, §4). Тело — `{ verseIds: UUID[] }`.

**Безусловный повторный анализ** — в отличие от `analyzeChapter`
(фильтрует по `DRAFT`/`FAILED`), этот эндпоинт анализирует **все** переданные
`verseId` независимо от текущего `status`, включая уже `ANALYZED` (полностью
перезаписывая существующий `VerseAnalysis`/`VerseWord[]`, как обычный
повторный анализ одного стиха через `POST /verses/{id}/analyze`). Стихов с
`status = ANALYZING` в переданном списке текущая реализация не оберегает от
повторной постановки — если это окажется проблемой на практике (два
параллельных батча трогают один стих), лечится отдельным тикетом, не
блокирует эту задачу.

**Батчинг LLM-вызовов.** `runAnalysis(List<Verse>)` (переиспользуется как
есть, см. ниже) отправляет **один** LLM-запрос на весь переданный ей список —
для `analyzeChapter` это ограничено естественным размером главы, для
произвольного списка `verseId` ограничения нет. Нужно разбить входной список
на чанки заранее (до вызова `runAnalysis`). Размер чанка —
`max-completion-tokens / 3000` (3000 токенов — ориентир на один стих с полным
разбором), но **не больше 20**; если `max-completion-tokens` не задан —
20. Чанки обрабатываются
последовательно в рамках одного HTTP-запроса (синхронно, без очереди/polling
— тот же паттерн, что уже применён у `analyze-all`, Virtual Threads делают
блокирующее ожидание LLM в потоке запроса дешёвым). Ответ — `202 Accepted` с
телом `{ verseIds: UUID[] }` (список принятых к анализу id, тот же формат,
что `AnalyzeAllVersesResponse` у `analyze-all`).

**Переиспользование.** Новый метод `VerseAnalysisService.analyzeVerses(List<UUID>
verseIds)`: загрузить `Verse` по id (пропустить не найденные/удалённые — не
ошибка), разбить на чанки (см. выше), вызвать существующий приватный
`runAnalysis(List<Verse>)` на каждый чанк по очереди. Никакой новой бизнес-
логики анализа — только сборка списка `Verse` и чанкинг, сам `runAnalysis` не
меняется.

## Frontend: страница массового просмотра/анализа

**Роут** `/sangraha/verses`, **ADMIN-only** на уровне роута (аналогично
тому, что весь write в sangraha — ADMIN; здесь и read по сути открыт бэкендом
всем, но сама страница имеет смысл только как инструмент ревью только что
загруженного/непроанализированного контента — гейтить на фронте).

**Данные** — `POST /api/v1/sangraha/verse` с телом `{ verseIds }` (см. выше)
при монтировании страницы. Источник списка `verseId`:
- если в URL есть query-параметр `id` (`useSearchParams().getAll('id')` — путь
  кнопки «Проанализировать недостающие примеры», см. ниже) — берётся оттуда;
- иначе (переход с кнопки «Открыть все стихи», без параметров) — читается из
  localStorage по ключу `sangraha.verseBatchIds` (JSON-массив строк; записывает
  его `DeclensionExamplesPanel`, см.
  `docs/frontend/pages/grammar-lesson-page.md` §2.2а). Хелперы —
  `frontend/src/utils/verseBatchIds.ts`.

**Список.** Таблица: `workTitleRu`/`chapterTitleRu`, `verseOrderIndex`,
`textIastPreview`, `status` (тот же бейдж/иконка по статусу, что уже есть на
`ChapterPage.tsx` — переиспользовать `STATUS_COLORS`/аналогичный маппинг, не
заводить второй). Клик по строке — `navigate(`/sangraha/${workSlug}/verses/${id}`)`
(существующий роут `VersePage`, §7).

**Кнопка «Анализировать все».** Видна всегда (не только при наличии
`DRAFT`/`FAILED` — в отличие от `ChapterPage`, здесь повторный анализ
`ANALYZED` стихов осмыслен, см. выше про безусловность), по клику —
`POST /api/v1/sangraha/verse/analysis` с телом `{ verseIds }` (весь список из
query-параметров или localStorage — тот же `ids`, что у загрузки страницы, см.
выше; выбор подмножества строк в этой версии не делается, отдельный тикет при
необходимости). Хук
`useAnalyzeVerses` — по аналогии с `useAnalyzeAllVerses`
(`frontend/src/hooks/useSangraha.ts`), `onSuccess` — инвалидировать запрос
`['sangraha', 'verse-batch', verseIds]` (ключ этой страницы), чтобы список
обновил `status` после ответа `202`.

**Точки входа.** Кнопка «Открыть все стихи» на вкладке «Примеры» урока склонений
(sangraha-service, фронтенд ходит напрямую, см. `sangraha-service.md` §9) — для
`ADMIN`. По клику кладёт все
`verseId` из `examples[]` в localStorage (`sangraha.verseBatchIds`) и
переходит на `/sangraha/verses` **без query-параметров** — страница
читает список из localStorage (см. выше). Детали —
`docs/frontend/pages/grammar-lesson-page.md` §2.2а. (Кнопка «Проанализировать
недостающие примеры» с `missingVerseIds` удалена вместе с quiz-service агрегацией.)

Прямого входа внутри самого раздела `/sangraha/*` в этой версии нет (не
блокирует — можно добавить отдельным тикетом, например ссылку со страницы
работы для непроанализированных стихов).
